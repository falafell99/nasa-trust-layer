# AGENTS.md: правила для агентов и людей проекта

Читать целиком перед первой правкой. Эти правила важнее удобства.

## 1. Метки уверенности

Перед каждым фактическим утверждением в документах, отчётах и ответах ставь метку:
- `[Точно]`: есть твёрдый источник (ссылка, открытая страница, измерение нашим кодом).
- `[Вероятно]`: сильный вывод из фактов, но прямого подтверждения нет.
- `[Догадка]`: заполняешь пробел. Если почти весь ответ догадки, скажи об этом первым.
Если не можешь проверить, пиши «не подтверждено». Не придумывай числа, ссылки, названия статей.

## 2. Честность чисел

- Каждое число в слайдах и README: источник (ссылка) или «наше измерение» + дата + хэш коммита + команда запуска + размер выборки.
- Всегда называй знаменатель: «доля ложных среди сработавших тревог» ≠ «доля записей с артефактами» ≠ «доля забракованных окон».
- Доверительные интервалы (бутстрап по записям или пациентам) для всех метрик результата.
- Негативный результат публикуем так же, как позитивный. Если модель хуже базовой линии, так и пишем.
- Тестовую часть не трогать при обучении и выборе порогов. Пороги замораживаются до демо.

## 3. Дисциплина заявлений (жюри)

Подробно в `docs/06-claims-and-prior-art.md`. Минимум:
- Не «первые в мире». Формулировка: «насколько нам известно из открытых источников».
- Не утверждать, что система валидирована на астронавтах или для космоса. Данные земные: реанимация, амбулаторные и носимые записи.
- Не называть CMO Digital Assistant бортовым или работающим в полёте.
- «Runtime» = потоковое исполнение + измеренные задержка и память на нашем ноутбуке, а не валидация непрерывного мониторинга.
- Плохой сигнал не означает «ложная тревога» и не означает «человек здоров».

## 4. Данные

- В репозиторий данные не коммитим (`data/` в `.gitignore`). Скачиваем локально по `docs/04-data-plan.md`.
- Сначала читаем лицензию и условия, потом используем. WESAD (некоммерческая лицензия) не используем.
- Без PHI. Только открытые наборы.
- Все сигналы приводим к 250 Гц **с антиалиасингом** (`scipy.signal.resample_poly`), не срезом `[::4]`.
- CinC 2015 и VTaC: для режима реального времени обрезать запись до момента тревоги (первые 300 с) **до любой обработки**. Данные после тревоги в публичных файлах есть, это утечка из будущего.
- Метки true/false никогда не попадают в признаки.
- Разбиение по записи/пациенту/субъекту, не по окну. Для BUT QDB первые три цифры ID записи — субъект.

## 5. Контракт интерфейсов (не менять без записи в decision-log)

```python
quality(window: ndarray[ch, n], accel=None) -> float      # 0..1, это балл качества, НЕ вероятность
verify(segment: {ecg1, ecg2, ppg, alarm_type, fs=250}) -> p_true   # 0..1
decide(q, p_true, alarm_type) -> {state, reason_code}
```
Виртуальный датчик отдаёт пакеты `{t, channel, samples}`. Остальной код не знает, что поток записанный.

## 6. Как работать вместе

- Свой журнал: `progress/logs/<имя>.md`, только дописывать. Формат записи:
  ```
  ## 2026-11-15 04:10 | <имя/агент> | <тема>
  Сделано: ...
  Результат: ... (числа с метками и командой)
  Не работает / риск: ...
  Следующий шаг: ...
  ```
- Перед работой `git pull --rebase`, после неё маленький коммит + `git push`.
- Чужие файлы в `docs/` не править молча. Хочешь поменять: пиши предложение в свой журнал и добавляй запись в `docs/10-decision-log.md`.
- Несколько агентов не должны одновременно менять формат данных и интерфейс. Формат и интерфейс — через контракт выше.
- Агентам отдавать изолированные задачи: парсер, тесты, визуализация, документация, слайды.
- Передача работы: `progress/handoffs/TEMPLATE.md`.

## 7. Гейт на код продукта

Пока лид не написал «одобряю» про `docs/03-product-design.md`, не пишем код продукта (модели, экран, виртуальный датчик). Разрешено: скачивание и чтение данных, подсчёт меток, проверка доступности, скрипты разведки данных, подготовка слайдов-скелетов.

## 8. Стиль общения лида с ассистентом (по его предпочтению)

Русский язык. Первым предложением оспорить предпосылку; метки уверенности; без комплиментов и воды; неудобная правда первой; без разогревающих абзацев. У тиммейтов могут быть свои предпочтения.
