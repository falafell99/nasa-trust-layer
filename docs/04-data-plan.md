## 2. Карточки наборов

### CinC 2015 (PhysioNet/Computing in Cardiology Challenge 2015)
- URL: https://physionet.org/content/challenge-2015/1.0.0/ ; файл https://physionet.org/files/challenge-2015/1.0.0/training.zip (322,9 МБ; весь ZIP проекта 352,4 МБ). [Точно по 3 моделям]
- 750 обучающих записей, WFDB (`.hea`, `.mat`), 250 Гц, 2 отведения ЭКГ + PPG и/или ABP (RESP не везде). Пять типов тревог: Asystole, Extreme Bradycardia, Extreme Tachycardia, VT, VF/Flutter. Метки true/false в файле `training/ALARMS` (по трём моделям формат «запись, тип, true/false»; **проверить по факту**, как закодирована метка: 0/1 или True/False).
- Лицензия: ODC-By 1.0, открытый доступ. 
- **Скрытые тестовые 500 записей недоступны.** Hold-out делаем из 750.
- **Нет сквозного ID пациента.** Разбиение по записи не гарантирует отсутствие пересечения пациентов. Формулировка в отчёте: «held-out public-record evaluation; patient overlap cannot be ruled out».
- **Ловушка 1, утечка из будущего:** в части записей есть 30 секунд после момента тревоги. Для real-time режима обрезать до первых 300 секунд (75 000 отсчётов) **до любой обработки**.
- **Ловушка 2:** PPG есть не во всех записях (Perplexity), у части только ABP. ECG+PPG-подмножество меньше 750: посчитать по `sig_name`. ABP за PPG не выдавать. Ответ 23 (со ссылкой на таблицу организаторов): 628 записей с PPG (в т.ч. вместе с ABP), 122 только с ABP; публичный `ALARMS` содержит ID, тип и метку 0/1. Не пересчитано по сигналам.
- Счётчики: 292 истинных / 458 ложных по двум моделям, 294/456 в одном источнике. Пересчитать.

### VTaC v1.1 (PhysioNet, релиз 14.09.2026)
- URL: https://physionet.org/content/vtac/1.1/ ; метки: https://physionet.org/files/vtac/1.1/event_labels.csv и `benchmark_data_split.csv` (по ~121,6 КБ). [Точно по 3 моделям]
- 5 037 размеченных VT-тревог после исключения Rejected/Uncertain (по ответу 23: 5 742 события размечены минимум двумя экспертами, 5 350 получили итоговое решение; не пересчитано), 2 376 — число исходных patient records до отбора, не число пациентов в размеченной выборке, ≥2 отведения ЭКГ + PPG и/или ABP, 250 Гц, WFDB. Метки True/False/Uncertain. Опубликован benchmark split.
- Лицензия: CC BY-SA 4.0 (копилефт: учитывать при публикации).
- **Не качать полный ZIP** (10,9 ГБ; распакованно 18 ГБ): в v1.1 добавили ≈12 000 неразмеченных записей в `waveforms/`. Нужна только папка `annotated_waveforms/`.
- Размер размеченной части на странице не указан. Прикидка ассистента: 18 ГБ / 17 131 окон ≈ 1 МБ на окно → 1 000 тревог ≈ 1 ГБ, **если файлы тянутся по одному** (структуру путей никто не проверил).
- **Ловушка:** окно 5 минут до тревоги + 1 минута после (Perplexity): резать на 5:00, как в CinC. События одного `record` не делить между train и test. Только VT.

### BUT QDB (Brno University of Technology ECG Quality Database v1.0.0)
- URL: https://physionet.org/content/butqdb/1.0.0/ ; файлы по адресу `https://physionet.org/files/butqdb/1.0.0/<ID>/<ID>_ECG.dat`, `_ECG.hea`, `_ACC.dat`, `_ACC.hea`, `_ANN.csv`. Лицензия CC BY 4.0. [Точно]
- 18 записей по ≥24 часа от 15 человек; ЭКГ 1 отведение 1000 Гц (Bittium Faros 180) + 3-осевой акселерометр 100 Гц; три эксперта + консенсус; классы 1 (видны P, QRS, T), 2 (шум, но QRS детектируется), 3 (QRS не виден), 0 (не размечено). Распределение времени по консенсусу (Gemini): Q1 59,21%, Q2 38,33%, Q3 2,46%. **В питче не использовать**: неизвестно, на каких записях и с каким знаменателем посчитано; часть шумных участков отбирали для разметки (ответ 23).
- Полный ZIP 2,2 ГБ (распакованно 4,2 ГБ). Размеры (по каталогу): 100001: ECG 166,1 МБ + ACC 49,8 МБ; 105001: 265,4 + 79,6; 111001: 172,9 + 51,9; 103001 и 104001: ≈166 + 50.
- **Критично: полностью размечены только три записи, остальные размечены частично (два окна по 20 минут). Три модели назвали три разные тройки:** 100001/111001 (Gemini), 100001/105001/111001 (GPT), 100001/103001/104001 (Perplexity). Общая только 100001. **Какие три записи полностью размечены, не проверено.** Как проверить: скачать `_ANN.csv` всех 18 записей (по 57–293 КБ), посчитать долю времени с консенсус-классом ≠ 0, выбрать три лучших, проверить, что в них есть Class 3.
- Первые три цифры ID — номер субъекта (100001 и 100002 — один человек). Разбивать по субъектам.
- **Схема CSV:** [Вероятно по Perplexity] 12 колонок, консенсус (начало, конец, класс) — последние три; строки — интервалы, не секунды; единицы начала/конца (секунды или отсчёты) **не проверены**; сверить с `ann_reader.m` из архива (ответ 23 утверждает: в отсчётах исходной ЭКГ 1000 Гц, консенсус — последние три столбца; не проверено). Неразмеченное (0) нельзя считать «хорошим сигналом».
- Нет PPG. Нет меток болезней. Тяжёлый дисбаланс классов: считать recall по Class 3, а не только macro-F1.

### MIT-BIH Noise Stress Test (NSTDB v1.0.0)
- URL: https://physionet.org/content/nstdb/1.0.0/ ; файлы `bw`, `ma`, `em` (`.dat` + `.hea`), ≈5,7 МБ; весь ZIP 67,7 МБ. ODC-By 1.0. [Точно]
- 360 Гц, 2 канала чистого шума (baseline wander, мышечный, электродное смещение), ≈30 минут каждый. Зашумлённые ЭКГ в наборе сделаны всего из двух исходных записей (118, 119): не считать независимыми пациентами.
- `em.hea` содержит gain=0: читать в цифровых единицах (`physical=False`); точная калибровка SNR при наложении на ЭКГ CinC неочевидна, поэтому уровни шума подписывать «условные». Ресемплинг 360→250 Гц: `resample_poly(x, 25, 36)`.
- Это синтетический эксперимент: не реальный космический шум, не облучение, не микрогравитация.

## 4. Известные ошибки в кодах из внешних ответов (не копировать вслепую)

- `ecg.p_signal[::4]` для 1000→250 Гц даёт алиасинг. Использовать `scipy.signal.resample_poly(x, 1, 4)`.
- `ann[2].value_counts()` для BUT ANN.csv читает не тот столбец и считает интервалы, а не время. Класс — в последнем столбце, длительность считать из начала/конца.
- Код для OSDR (`requests.get(...osdr.../files/575).json()['studies']...`) опирается на непроверенную схему JSON: скачивать CSV вручную из браузера.
