# 03. Дизайн продукта: Trust Layer (версия v1, черновик на одобрение лида)

Статус: **не одобрен** («одобряю» не сказано). Вариант B (проверка тревог + шлюз качества) лид зафиксировал словами «ок, фиксируем». Эта версия включает всё, что решено или предложено после первой версии (Project doc `design/trust-layer-design.md`, v0). Изменения помечены **[v1]**. Метки: [Точно] / [Вероятно] / [Догадка].

## 1. Идея и зачем

Слой между датчиком и экипажем для миссий на Луне и Марсе. Когда простое правило (как на мониторе) поднимает тревогу по ЭКГ, слой за секунды отвечает на два вопроса: (1) можно ли верить сигналу, (2) если можно, событие настоящее? Работает офлайн, на небольшой модели, без обучения на лету. Исходная тревога никогда не скрывается, только подписывается.

Проблема и числа: `docs/02-problem-evidence.md`. Положение среди существующего и что можно заявлять: `docs/06-claims-and-prior-art.md`.

## 2. Цели, не-цели, анти-цели

Цели:
- Главная проверяемая цель: полный пайплайн (шлюз качества + согласованность каналов) сохраняет настоящие тревоги и уменьшает ложные лучше, чем тот же детектор без этих проверок.
- Работающий офлайн-прототип: «виртуальный датчик» + экран + статусы.
- Честные метрики с доверительными интервалами и подписанные ограничения.

Не-цели:
- Не диагностика, не медицинское изделие.
- Не LLM-ассистент. LLM, если успеем, только перефразирует шаблонную карточку.
- **Не непрерывный поиск событий в потоке.** [Точно] У нас нет открытого непрерывного набора с ЭКГ+PPG и размеченными критическими событиями. CinC 2015 даёт проверку уже сработавших тревог. «Ложных тревог в час» из него не вывести. Если заявлять поиск событий, нужен непрерывный набор вроде VitalDB Arrhythmia; но там размечены только выбранные участки около 20 минут, нет отдельных классов VF и асистолии, сырые сигналы берутся из родительского VitalDB (95 ГБ), лицензия расходится (PhysioNet CC BY 4.0, vitaldb.net CC BY-NC-SA 4.0). Это работа после основных этапов, не на эту ночь.
- Не WESAD и не стресс.
- Не своё железо на этом хакатоне.

Анти-цели: см. `docs/01-situation-and-goals.md`.

## 3. Ограничения

См. `docs/01-situation-and-goals.md`. Ключевое: открытые данные, офлайн, небольшие модели, ноутбуки, подача до 16:00.

## 4. Продукт

Пайплайн:
```
виртуальный датчик → скользящий буфер → триггер (правило) → шлюз качества
→ проверка события (ЭКГ-отведения + PPG) → решающий блок → экран + шаблонная карточка
```
- Триггер имитирует монитор. В CinC 2015 тревога уже есть, в демо её даёт запись.
- Шлюз качества считается постоянно на коротком окне и дёшево. Проверка события запускается по тревоге.
- **[v1]** Разделить короткое окно качества (секунды) и длинную историю буфера (минуты): они решают разные задачи.
- Что такое «буфер 5 минут»: [Точно] CinC 2015 даёт ровно по 5 минут до тревоги. Буфер это скользящая память последних 5 минут сигнала для проверки события. Объём ≈450 КБ (250 Гц × 3 канала × 2 Б × 300 с).
- В продукте используем только то, что есть у носимых датчиков: ЭКГ (до двух отведений) и PPG. Канал ABP из CinC 2015 в признаки не берём, ABP за PPG не выдаём.
- **[v1]** Поддержка отсутствующих каналов считается нормой (пропал PPG, один отведение): шлюз считает пропуск плохим сигналом, а не ошибкой.

### Статусы (формулировки рабочие, обсуждаются)

- «Действуй» (красный): «Похоже на настоящее. Проверь человека сейчас».
- «Проверь» (жёлтый): «Сигнал плохой, события не исключаем. Проверь датчик и человека». При сомнении всегда жёлтый.
- «Скорее ложная» (серый): только при хорошем сигнале и отсутствии признаков события. Тревога остаётся видимой, подавление подтверждается человеком. **[v1, предложение]** переименовать в «Не подтверждено», чтобы подпись не подталкивала игнорировать; проверить на 3–5 людях.
- Под статусом одна строка причины («ЭКГ показывает ноль, но пульс по PPG 74. Вероятно, отошёл электрод»).
- Карточки действий: шаблоны по типу тревоги, помечены «иллюстративно» (открытого набора лётных протоколов нет).

### Принципы

1. Исходная тревога никогда не пропадает.
2. «Скорее ложная» возможна только при хорошем сигнале.
3. При сомнении жёлтый.
4. Одна строка причины.
5. Один сигнал не превращается в четыре задачи для экипажа.
6. **[v1]** Балл качества q **не вероятность**. Так и называем: «балл качества».
7. **[v1]** Отложенное решение («проверь позже») нужен срок и правило эскалации (IEC 60601-1-8 по рекомендации GPT-критика; [Догадка] ссылка из его ответа не проверена).

### Открытый спор по интерфейсу (решает лид)

[Вероятно, предложение GPT и документа-вердикта] Три статуса смешивают три разные вещи: качество сигнала, наличие события и необходимость действовать. Предложение: показывать **две независимые оси**: «Качество измерения» (хорошее / сомнительное / ненадёжное, с причиной) и «Находка по событию» (подтверждено / не подтверждено / не исключено), а красный/жёлтый/серый выводить из них. Плюс: убирает опасное сокращение «шумный сигнал = ложная тревога». Минус: сложнее объяснить жюри за 30 секунд. Решения пока нет (см. `docs/10-decision-log.md`, D-08).

## 5. Модели (без больших LLM в v1)

- Проверка события: градиентный бустинг на признаках окон (пульс по отведениям и PPG, согласие каналов, устойчивость события во времени, размах, доля плоской линии, шум). **[v1]** GPT-критик советует начинать с нескольких интерпретируемых признаков; начинаем с 10–30, расширяем только при пользе. Компактная 1D-CNN **вынесена из критического пути**: пробуем только после V0–V3, берём, если заметно лучше.
- Шлюз качества: небольшая модель на признаках шума, амплитуды, плоской линии (и движения, где есть акселерометр). Выход: балл q от 0 до 1. **[v1]** Основной шлюз работает только на ЭКГ (+PPG); версия с акселерометром — отдельный эксперимент, потому что акселерометр есть только в BUT QDB и вход обучения и демо должен совпадать.
- Решающий блок: правила на q, p_true и типе тревоги. Пороги выбираются на валидации с асимметричной ценой (пропуск настоящей тревоги в 5 раз хуже, как в официальном скоринге CinC 2015) и замораживаются до демо. [Точно] коэффициент 5 это формула PhysioNet 2015, не клинический стандарт и не уровень риска NASA.
- Все сигналы приводим к 250 Гц с антиалиасингом (`resample_poly`).
- Размер модели, время инференса и память измеряем на ноутбуке. Про плату пишем «ожидаем, не измерено».
- **[v1]** Базовая линия «только тип тревоги» обязательна (GPT: простой классификатор по типу тревоги может быть сильнее наивных линий).

## 6. Контракт интерфейсов

```python
quality(window: ndarray[ch, n], accel=None) -> float   # 0..1, балл качества (не вероятность)
verify(segment: {ecg1, ecg2, ppg, alarm_type, fs=250}) -> p_true  # 0..1
decide(q, p_true, alarm_type) -> {state, reason_code}
```
Виртуальный датчик отдаёт пакеты `{t, channel, samples}` из записей. Остальной код не знает, что поток записанный.

## 7. Подходы, которые рассматривали

- A. Главная задача WESAD (стресс): отклонён (метки не про критические события, лицензия некоммерческая).
- B. Верификация критических ЭКГ-тревог (CinC 2015) + шлюз качества: **выбран лидом**.
- C. Оба блока наравне: отклонён, размывает фокус.
- Предобученный PPG-энкодер (PaPaGei): не берём (несовпадение домена).
- LLM поверх: опционально, последним, только пересказ шаблона.
- **[v1, внешний вариант, не принят]** SensorTrust/SignalTrust (GPT и документ-вердикт): главное обещание сместить на «надёжность измерения и понятную реакцию на неопределённость», проверку реанимационных тревог сделать вторым экспериментом, основным взять BUT QDB. Позиция ассистента: не соглашаться, потому что у BUT QDB 18 записей от 15 человек, полностью размечены три, метки говорят о качестве, а не о пропущенной тревоге; оставить основным CinC 2015 (+VTaC), BUT QDB отдать шлюзу. Риск такой позиции: объём работы, поэтому V0–V3 сокращены до V0 и V3 + опциональные V1, V2, CNN убрана. Решает лид.

## 8. Данные (кратко)

Подробно: `docs/04-data-plan.md`. Роли:
- CinC 2015 (750 обучающих записей): проверка тревог.
- VTaC v1.1: второй набор тревог (только VT), есть готовое разбиение по пациентам.
- BUT QDB: шлюз качества и длинный ECG+ACC replay.
- MIT-BIH NST: контролируемый шум (синтетика, так и подписываем).
- Записи Apple Watch команды: демо шлюза, без меток.

**[v1] Шлюз как перенос между доменами.** Метки качества есть только в BUT QDB (одно отведение, носимый Faros, здоровые, тревог нет). Метки тревог только в CinC/VTaC (реанимация, без меток качества и без движения). Значит шлюз, обученный на BUT, при применении к CinC работает как перенос. [Догадка] Выигрыш V1 на CinC может быть нулевым. Публикуем результат любой.

## 9. Демо

**[v1] Две отдельные сцены**, не склеивать как одного человека:
1. Поток BUT QDB (реальный 30-минутный кусок с движением по акселерометру) через шлюз: «качество падает, шлюз говорит проверь датчик». Это не демонстрация аритмии.
2. Тревога из CinC 2015 (ЭКГ+PPG) через проверку: статус, причина, карточка, офлайн.
Дополнительно: запись Apple Watch (чистая и намеренно испорченная) для шлюза, без выводов о здоровье. Запасное видео записать заранее.
PPG при движении есть только в PPG-DaLiA (2,7 ГБ); берём, только если готовы CinC и BUT.
