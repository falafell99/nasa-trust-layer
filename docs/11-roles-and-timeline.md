# 11. Роли и таймлайн

Метки: [Точно] / [Вероятно] / [Догадка]. Статус: **предложение**, ждёт «одобряю» по дизайн-документу и решения лида по ролям. Имена тиммейтов лид подставит сам. До «одобряю» разрешены только проверки данных (скачать, прочитать, посчитать метки).

## 1. Роли (три человека + их агенты)

| Роль | Зона | Выходы |
|---|---|---|
| A. Данные и оценка | скачивание, чтение WFDB, пересчёт знаменателей, hold-out, метрики, бутстрап | `progress/logs`, таблицы чисел, заморозка hold-out |
| B. Модели и решающий блок | признаки, шлюз качества, проверка события, пороги, `decide()` | функции `quality`, `verify`, `decide` по контракту `docs/03` |
| C. Демо, интерфейс, питч | виртуальный датчик, экран, статусы, слайды, запасное видео | запускаемое демо, 7 слайдов или видео, репетиция |
| Лид (общая) | решения D-07, D-08, Q9; финальные заявления; подача | записи в `docs/10` |

Агенты каждого человека пишут в журнал своего человека, не в чужой.

## 3. Порядок работ и зависимости

1. Данные (A) → без них нельзя ни модель, ни числа.
2. Контракт интерфейсов (B, C) фиксируется сразу, чтобы C мог делать экран на заглушках.
3. Метрики (A) зависят от замороженного hold-out (до подбора признаков).
4. Пороги (B) подбираются на валидации, не на hold-out.
5. Экран (C) переключается с заглушек на реальные результаты к 10:30.
