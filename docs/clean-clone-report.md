# Чистый клон и запуск демо

Дата проверки: 2026-11-15 (Будапешт). Тест выполнен на свежем `main` клоне `6be1c06` на macOS Apple Silicon, Python 3.14.3. Репозиторий клонирован через `gh repo clone falafell99/nasa-trust-layer`; доступ к приватному репозиторию был авторизован.

## Результат

- [Точно, наше измерение] Клон чистый, README-команды выполнены без изменений: `python3 -m venv .venv && .venv/bin/pip install -r requirements.txt`, затем `./run_demo.sh`.
- [Точно, наше измерение] Зависимости установились; среди закреплённых версий — FastAPI 0.163.0, Uvicorn 0.54.0, NumPy 2.5.4, SciPy 1.18.1, pandas 3.1.1, scikit-learn 1.9.1, WFDB 4.3.1 и PyTorch 2.15.0. Для установки был скачан wheel PyTorch размером 138.6 MB.
- [Точно, наше измерение] `./run_demo.sh` запустил Uvicorn; `/` отвечает HTTP 200. Запрошен README-сценарий `/?scene=true_red`, затем `/api/scenes`.
- [Точно, наше измерение] Экран с тревогой не получен: API вернул `b: null`, `a: null` и ошибки `FileNotFoundError` для `data/vtac/benchmark_data_split.csv` и `data/butqdb/111001/frag_ECG_t67740_180s.bin`. В чистом клоне каталог `data/` не содержит этих файлов. Время «клон → экран с тревогой» поэтому не измеримо: тревожный экран не появился.
- [Точно, наше измерение] README отсылает скачивать данные по `docs/04-data-plan.md`, но точный минимальный набор для демо и подготовка требуемого BUT QDB-фрагмента в инструкции запуска не описаны. Код демо обращается к меткам и сигналам VTaC и к ECG/ACC/ANN BUT QDB; он перебирает VTaC события для построения сцен. Поэтому подтвердить, что достаточно маленькой загрузки и не нужны крупные данные, по чистому клону не удалось.

## Проверка без сети

- [Точно, наше измерение] Перед повторным запуском Wi-Fi на `en0` был отключён командой `networksetup -setnetworkserviceenabled 'Wi-Fi' off`; `scutil --nwi` показал отсутствие IPv4/IPv6-состояний и недоступность сети. В `networksetup -listallnetworkservices` отдельной службы Ethernet нет; перечислены Thunderbolt Bridge, Wi-Fi и iPhone USB. После проверки Wi-Fi восстановлен.
- [Точно, наше измерение] Без сети `./run_demo.sh` снова запустился, `/` и `/api/scenes` вернули HTTP 200. В API повторились те же ошибки отсутствующих файлов. Это подтверждает локальный запуск сервера, но не успешное офлайн-демо с тревогой.
- [Точно, наше измерение] Поиск `rg -n -i 'requests|urllib|http|https|socket|urlopen|fetch\(' src/trust run_demo.sh requirements.txt` не нашёл исходящих HTTP-клиентов в Python-коде старта. Единственный `fetch` в UI обращается к относительному адресу `/api/scenes` на том же сервере. В `run_demo.sh` запускается локальный Uvicorn на `127.0.0.1`; зависимости с `requests` присутствуют в окружении, но проверенный путь запуска их не вызывает.

## Что исправить

1. [Точно] Дать воспроизводимую инструкцию подготовки ровно тех данных, которые использует демо, включая способ создания `frag_ECG_t67740_180s.bin` и соответствующего ACC-фрагмента.
2. [Точно] Перед запуском проверять необходимые файлы и показывать понятную ошибку с именем набора и инструкцией загрузки, вместо пустых сцен.
3. [Вероятно] Уточнить `requirements.txt` или разделить demo-зависимости и зависимости исследований: чистая README-установка скачивает PyTorch wheel на 138.6 MB, хотя проверенная команда демо не обращается к PyTorch.

Команда запуска из корня клона: `./run_demo.sh`; проверенные URL: `http://127.0.0.1:8000/?scene=true_red` и `http://127.0.0.1:8000/api/scenes`.
